## What completion means

Port product behavior, not old execution authority. Native Pi remains available directly; independent resources/controllers do not require an agent or a replacement runtime. Reusing a component does not certify it against new provider, persistence, scope or lifecycle semantics. Strong publication requirements must not burden every scratch byte or disable ordinary working tools.

Maintain attribution/licenses for copied/adapted code. Dependency/SDK approval precedes implementation; the ledger authorizes no new purchase or cloud expenditure. Use real browser evidence for scroll/focus/layout/uploads, stored revisions/receipts for resource effects, hard crashes for recovery and real provider tests for claimed environment guarantees. Mocked UI/unit examples are complementary, not substitutes.

A47 composes native agent, readonly references, writable document, installed chat/editor/custom viewer, proposal/acceptance/save/reload. It also exercises provider substitution, independent add/remove/failure cleanup, published versus private working views, readonly/dirty/disconnected negatives and unopened-document operations. The background reference example runs without a browser; the coding example proves coherent file/shell acquisition and honest cancellation/restart. These do not manufacture clinical expert acceptance or full Hub M1 qualification.

See [ACCEPTANCE.md](../acceptance/ACCEPTANCE.md), [PI-COMPLEMENT.md](../architecture/PI-COMPLEMENT.md#three-reference-applications) and [ROADMAP.md](../architecture/ROADMAP.md#implementation-packet-reconciliation). All P01–P14 and earlier evidence obligations remain; this ledger makes preservation and deliberate corrections inspectable.

## Partial Markdown port

It adapts acceptance to strict v4 instance/scope/view/revision/buffer checks and the exact transactional flush path. Changed proposals do not rebase implicitly; late/reentrant edits remain protected. Native patch recovery retains its exact transformed bytes through public Pi memo before conditional publication. Public tests, SIGKILL recovery and the isolated document consumer exercise this slice.

The optional `markdown-editor.tsx` renderer now uses React 19.3.0 and Tiptap 3.31.3, matching the pinned v3 recipe's Tiptap generation. It retains rich/source modes, formatting controls, proposal review and explicit save/conflict controls while borrowing the v4 controller. Per-editor Marked state disables raw HTML without changing the host parser. Eleven DOM scenarios exercise real Tiptap/React with SQLite, including paste safety, read-only state, new documents and late acknowledgements. An isolated tarball consumer checks strict declarations, repeats those controls and builds a browser bundle without the native kernel. No upstream source was copied. The next renderer increment adds local heading navigation and mode-local selection retention using native Tiptap documents/bookmarks. DOM tests cover backward selection direction, unchanged bytes, source edits and controller replacement; a whitespace-only edit regression ensures structurally equal headings receive a fresh native document target. The mounted command increment adapts v3 selection inspection and heading navigation using native ProseMirror positions and mode-specific source offsets. A separate mount/projection identity prevents stale targets from surviving renderer replacement; human outline controls share the same command. Public DOM and native composition tests plus installed archives/recipes exercise this behavior. Proposal review now independently implements the pinned v3 same/add/remove line presentation and two-line context folds, retaining exact before/after snapshots and existing v4 acceptance. Its matrix is capped at 250,000 cells with a disclosed coarse replacement fallback; v3 used an unbounded matrix. No legacy source was copied. Tables/assets and browser qualification remain pending. Candidate revisions and raw commands are recorded in [PARTIAL.md](../implementation/PARTIAL.md).

## Partial chat port

The new optional native controller and React chat retain pinned v2 composer behavior for IME, Shift+Enter and externally prevented Enter. They retain a 60-row initial history, 40-row expansion, stream-to-final assistant identity, developer reasoning/tool details and host custom cards. V4 caps mounted transcript rows at 200 and pins required cards independently. Native acknowledgements clear only the captured draft; unknown admission retains a request for lookup or exact retry. This deliberately replaces v2's optimistic clear/restore path, which did not distinguish an unacknowledged commit. Tool results bind to the actual preceding invocation rather than assuming model call IDs are globally unique.

Tests drive real native entries and fake-model streams through React in a DOM environment. No legacy source was copied. Actual browser scroll anchoring, focus, uploads and installed styling remain pending. The public [UI guide](../../packages/ui/README.md#optional-native-chat) documents host ownership and the raw-view privacy boundary.

The next chat increment adapts v2 `PiTimelineMessage`/`MessageResponse` formatted assistant text to a private pinned Marked lexer and React elements. It preserves separate native text parts, row identity, streaming copy disablement and v4's existing one-newline copy separator. This is a new implementation; no legacy renderer code is copied. HTML stays literal, generated images do not load, and only validated absolute HTTP(S) links are clickable. Entity decoding uses the pinned public `entities` package rather than HTML insertion. Syntax highlighting, link-copy affordances, mentions and browser selection continuity remain separate port obligations.

The history increment uses native fork-aware `Conversation.entries` to read records outside the active context. It preserves a fixed inclusive upper bound, opaque pagination and one retained page. An explicit history section protects active streaming row identity and keeps historical records out of current action-card callbacks. Total mounted transcript rows stay bounded while browsing. Real native reset/head/fork and DOM tests cover controls and stale replies. This is new code over current native APIs; actual browser anchoring and selection remain pending.

## Adjacent chat tools
