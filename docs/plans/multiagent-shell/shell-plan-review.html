Multi-agent workspace shell

OWNER DECISION

A new workspace layout, not a rewrite: a third value on the existing WorkspaceAgentLayout switch, composed as a sibling to today's plugin-tabs shell, reusing components a spike already proved. It gives the multi-agent vision a home — Inbox / Work / Agents / Library / Search over one workspace, with chat as a column beside a view rather than a page you switch to.

The shape

Nav is domains; the vertical plugin rail is tools. The workbench is one component with four mounts. Deterministic Views sit beside agentic Threads.

Why this is cheap — and where it isn't

Proven by the spike
  • The IA renders from shipped components — 19 files, only 5 touching production packages
  • Real file tree against the real filesystem
  • InboxOverlay / AutomationPanel render as pages unchanged
  • ArtifactSurfacePane nests safely (dock and thread canvas)
  • Page/dock center modes, dock genuinely unmounted in page mode
Not proven by anything
  • The chat is a visual fixture in both places it appears — disabled send button, literally labelled “composer visual only”
  • The thread transcript is a playground mock
  • All entity data is fixture (1,107 lines)
  • Zero component tests for the shell
  • Mobile: never exercised
The honest headline. The spike proves the frame. It proves nothing about a live multi-agent transcript inside that frame. That is slice L4, and it is the highest-risk item in the plan.

The 13 questions

Ordered by how much they change the build. Each has a recommendation; the plan is written assuming the recommendations, so a different answer means a rewrite of that slice.

1Routing / location ownership BUILD-DEFINING

Who owns the canonical shell location and route lifecycle? Both reviewers named this the deepest gap. The package has no router by contract — an existing prop says so in as many words. The spike violated that with a module-global mutable ref.

#OptionConsequence
ASplit (recommended). Package owns ShellLocation state + navigate(); host owns URL serialization.Consistent with today's contract. Deep links, back/forward and refresh all become stated behavior.
BHost owns location entirely; package is fully controlled.Cleanest boundary, but every host re-implements five domains of routing.
Recommendation: A — it matches how project settings and new-tab hrefs already work.
Cost of the answer: Slice L1.5, one session. Answer changes the reducer shape and the package boundary.
2Nav extensibility — and the Inbox paradox BUILD-DEFINING

The ruled IA is fixed and ordered. But Inbox itself arrives today as a plugin contribution (appLeftActions: [{ id: "inbox", … order: 10 }]). A closed IA either hardcodes a destination the plugin owns, or keeps a contribution point the IA claims to have closed.

#OptionConsequence
ANamed section slots (recommended). IA fixed and ordered; plugins slot into declared sections.Keeps plugin extensibility honest without letting plugins reorder the IA.
BTools rail only — plugins never appear in nav.Simplest, but demotes existing plugin surfaces.
CIA fully closed; Inbox promoted into the shell, ask-user loses its nav entry.Cleanest IA, but a real behavior change for a shipped plugin.
Recommendation: A.
Cost of the answer: Shapes L2a. B or C means editing the ask-user plugin.
3Library persistence BUILD-DEFINING

Where do saved views live? #1355's ConsoleCollection cannot hold them — it is navigation metadata that explicitly owns no Thread, Task, Intention or Automation.

#OptionConsequence
ADescriptor-local / unsaved for the first tranche (recommended).Ships L3b now; defers the store until the ratified View work lands.
BWorkspace settings.Available today, but settings is not a collection store.
CA new plugin store.Correct long-term, a slice of its own.
Recommendation: A — do not invent a store before the View contract exists.
Cost of the answer: Gates whether L3b ships in the first tranche.
4Nav supersession vs #1355 Slice 3 BUILD-DEFINING

Does this plan's fixed IA supersede #1355 Slice 3's left-pane organization for the workspace-shell layout, with Slice 3 retaining plugin-tabs? This is a #1409 decision, not a #1355 Gate 1 item — that gate's four questions are about collection ownership and never rule on shell nav.

#OptionConsequence
AYes, scoped supersession (recommended). This IA owns workspace-shell; Slice 3 owns plugin-tabs.Both plans proceed without a merge conflict in the nav.
B#1355 Slice 3 owns nav in both layouts.Then L2a is deleted and the shell inherits Console organization.
Recommendation: A.
Cost of the answer: Without an answer, L2a and #1355 Slice 3 will collide.
5Contextual chat beside a view SCOPE

Chat beside a view (not a thread) has no session to attach to. The spike never proved a live composer at all.

#OptionConsequence
AExplicit post-v0 non-goal (recommended). L7 may complete without it.Honest. Chat beside a thread (L4) still ships.
BPrerequisite to L7 — mint an ephemeral thread per view.Adds a session-lifecycle design to the critical path.
Recommendation: A.
Cost of the answer: B adds at least one slice and a lifecycle question.
6Export surface & semver posture SCOPE

Round 1 proposed exporting five visual internals. Withdrawn: the root entry states every export is deliberate, and a layout selected inside the package needs none.

#OptionConsequence
AInternal package layout (recommended). Zero or one deliberate export.No consumer coupling to private chrome.
BPublic headless seam.Only if a named external consumer requires it.
Recommendation: A, unless you can name the consumer.
Cost of the answer: A is strictly cheaper.
7Search / palette scoping SCOPE

Search is a nav domain and ⌘K is an existing chat-pane palette. Two things called search.

#OptionConsequence
ADomain-scoped Search page + existing palette (recommended).What the traits matrix assumes.
BOne palette scoped across all five domains.Nicer end state; a slice of its own.
Recommendation: A for v0, B as follow-on.
Cost of the answer: B is not costed in this plan.
8Chat-pane behavior in the shell SCOPE

Confirm off for v0: splitting, palette-open-in-new-pane, multi-pane restore. Note splitting is on in plugin-tabs today, and turning it off requires trait-gating a call site that is currently unconditional.

#OptionConsequence
AAll three off for v0 (recommended). One thread pane.Matches “1 Thread = 1 job”. Adds one trait-gate to L1.
BKeep splitting on.Then a job's timeline can be split across panes — contradicts the vision.
Recommendation: A.
Cost of the answer: Adds a small amount of work to L1.
9Attention data source & polling cost RISK

Five domains with counts and badges implies five subscriptions. Nothing in the plan costs this.

#OptionConsequence
AName the source and interval now.Prevents a performance surprise at L2a.
BShip counts absent, measure later.L2a already treats zero/absent as a valid state.
Recommendation: B for the first tranche, A before L7.
Cost of the answer: Unpriced either way — flagged honestly.
10Classic-layout deprecation line RISK

Three layouts is a permanent tax: the traits matrix must be filled for all three, forever.

#OptionConsequence
APut classic on a deprecation path with a date.Caps the tax.
BKeep all three indefinitely.Every future layout decision is a 3-column choice.
Recommendation: A — name the date even if it is distant.
Cost of the answer: Affects every future slice, not this one.
11Touch reachability RISK

Flyouts are hover-driven. The spike never passes mobileShellEnabled, so the mobile sheet path is unexercised by every claim in the plan.

#OptionConsequence
ADeclare mobile out of scope for v0, explicitly.Honest; the current claims do not cover it.
BDesign the mobile shell now.A separate design pass.
Recommendation: A.
Cost of the answer: B is not costed.

What sign-off means

Answering the 13 questions unblocks four beads — L1, L1.5, L2a, L3a — and nothing else. The remaining seven wait on the engine gate, the #1355 gate, or each other. #1401 was ratified on 2026-08-26, so the premise is settled.

The plan deliberately does not ask you to approve the vision — that is already ruled in #1399. It asks you to approve a route, and to settle the thirteen places where the route had to guess.
