Gate 1 · Plan approval

Job Thread v0 — 1 Thread = 1 job

OWNER DECISION

A projection, not a new Thread: several per-agent Pi sessions merged into one job timeline via a stateless relay, with typed handoffs, centrally-enforced caps, and an honest failure/restart contract. K7 demo — "grow audience 1,200 → 5,000" — proves it with two fleet agents (worker/reviewer) and one Objective.

Round 2 (folds fresh-eyes + cross-model review) · PR #1403 · Issue #1399 · Branch weekend/jobthread-v0-plan · No implementation before owner sign-off

Verdict on round 1 was revise at commit 9e42e893a — this document (2e9d4ba41) is the answer to that verdict. 2Relay vs. the ratified native agent-to-agent binding

OptionsUnblocks / costs
Decision 24 already ratifies a native in-process binding (input-required, two-way chat, no MCP loopback) for internal agent-to-agent consumption — it is available, not forbidden.

Relay (proposed) — a stateless, non-agent, non-Seat function over runWithWorkspaceAgent; no new agent-facing capability.

Native binding — build the ratified mechanism now instead.		 Relay unblocks: no new authority-bearing host seam, no long-lived scope, fully deletable, caps enforced centrally outside agent code.
Native binding costs: agents gain a direct calling capability that must then be scoped, audited, and capped per-agent rather than in one place.
Recommended: relay. This is a live product choice, not a compliance requirement — v0 picks the cheaper, deletable shape.

4Post/Run boundary — what crosses seats?

OptionsUnblocks / costs
Confirm narrow crossing — only the settled final assistant message (message-end.final, gated on non-willRetry) and relay-authored system handoff markers cross seats. No tool calls, no intermediate messages, no private reasoning. Confirms: each seat's private reasoning/tool trace stays reachable only by drill-down — the demo's privacy and noise story. A wider boundary would need re-litigating the handoff tool and the merged-timeline renderer.
Recommended: confirm the narrow boundary. This is the only shape in the plan; no alternative is proposed.

6Context truncation and budget — confirm both out-of-scope shapes

OptionsUnblocks / costs
Confirm — oldest-first truncation only, no summarization (a summarizer would be an unreviewed model call inside the relay); per-Thread spend is out of v0 because MeteringRunScope has no job/thread/participant dimension today. A real budget needs a job dimension threaded through the reservation path — named explicitly as v1 work, not a v0 claim.
Recommended: confirm both. Building either now would be new unbudgeted scope disguised as v0.

8Acceptance bar — fixture-driven gate, live-model as labelled smoke?

OptionsUnblocks / costs
