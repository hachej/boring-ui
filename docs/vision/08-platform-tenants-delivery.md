# 8. Platform, tenants and delivery

## The split

The platform repository ships neutral substrate: release identity,
installation, activation, runtime modes, upgrade reconciliation, authority,
durability, Views, agents. Tenants (Seneca first) own offers, pricing,
packaging of the offer, creator agreements, hostnames as presentation and
go-to-market sequencing. A commercial decision never reorders the kernel;
kernel sequencing is never justified by an unnamed offer.

Seneca is the first consumer and the first proof host. The recorded default
is that it pulls a release by digest from the platform's stores; who owns
provisioning, secrets, migrations and backups for an installed product is not
yet ruled. That delivery path is outside the first epic and named as an open
obligation.

## Execution home

This repository is the execution home for the journey. The interface-first
port into a new repository stands as doctrine and is demoted to an
evidence-triggered later step; nothing has been ported and its beads are
deferred. The old numbered milestone orders in the ratified pack are
dependency rationale, not a schedule.

## The factory is an engineering engine

Work is planned as beads meeting a definition of ready (what, proof path,
file scope, fits one session), dispatched from DIRECTION alone, built in
isolated worktrees, reviewed fresh at an exact commit, and merged by an owner
decision at a demonstrated URL. Human gates sit at protected boundaries —
today, plan approval and merge approval as Inbox items; enforced automatic
admission of ordinary work is the intended rollout and is not yet enabled. The curator never operates beads, worktrees
or pull requests; those are internal mechanisms behind an authoring job.
A gate that needs the founder to approve every private adaptation has moved
the bottleneck, not removed it.

## Honesty rules that govern every claim

Documentation may specify explicitly unbuilt targets but may not claim an
implementation guarantee before it is demonstrated. Missing proof is not a
pass. A false close is reopened with an incident note. Refusal-only
implementations earn partial credit and never close a feature. Process
artifacts exist only when they hard-gate a named capability.

## What waits

Public marketplace and discovery, creator revenue share, owned compute,
specialist models, cross-tenant learning, remote hosts as a general tier,
and the new-repository port — each behind its own named trigger.
