Who owns the MCP connection?

R2 REVIEW FIXES INTEGRATED

Answer: neither each AgentApplication nor Workspace. Full-app owns the request-scoped MCP transport; the process-lifetime delegate controller owns bounded receipts; each admitted background task owns one narrow Core-issued execution lease through terminal collection while raw scope/gateway remain in Core.

  Note over Ctrl,GW: Shutdown stops admission; aborts; waits bounded grace; fences late settlement; releases once; then gateway may close.

Lifecycle outcomes

EventRequired behavior
Create/select/admitAuthenticate each request → strict Workspace default → dedupe → credential rate/concurrency + global capacity → one narrow task lease only for new work.
Async commit / lost deliveryLease attach + stored receipt is the observable commit before response attempt. Pre-commit abort cancels admission; post-commit disconnect does not cancel; retry returns same receipt.
Cross-tool same keyOne shared task. Start returns receipt; synchronous call waits. First admission freezes origin cancellation; duplicate waiter abort is local.
PollSame/reconnected client may poll; every call reauthorizes disclosure and never reacquires execution authority.
RevocationGateway checks remain authoritative through accepted send. Before acceptance effect rejects; after acceptance stream/artifact may finish but status remains denied.
Completion/TTLAll terminal states release task authority; receipt alone remains until TTL, then prunes.
Process restartLoses tasks/leases/receipts; no recovery; old id not found; retry may duplicate.
ShutdownStop admission → abort → wait required 100..300,000 ms grace → fence never-settling late work and logically release once → gateway may close.
