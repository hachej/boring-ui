Who owns the MCP connection?

REVIEWED REVISION

Answer: neither each AgentApplication nor Workspace. Full-app owns the request-scoped MCP transport; the process-lifetime delegate controller owns bounded receipts; each admitted background task owns one AgentGateway execution lease through terminal collection.

Lifecycle outcomes

EventRequired behavior
Create/select/admitAuthenticate each request → strict Workspace default → dedupe → per-credential rate/concurrency + global capacity → one task lease only for a new record.
PollSame/reconnected client may poll; every call reauthorizes disclosure and never reacquires execution authority.
Async disconnectDoes not cancel after start receipt; task record and lease continue independently.
Synchronous disconnectRequest abort cancels, projects canonical canceled, releases slot/lease once.
RevocationDenies new starts/status; admitted async task may finish but remains undisclosed while revoked.
Completion/TTLAll terminal states release task authority; receipt alone remains until TTL, then prunes.
Process restartLoses requests, tasks, leases, receipts; no recovery promise; old id not found; retry may duplicate.
ShutdownStop admission, abort tasks, await exact cleanup, then close application-owned gateway.
