# Implemented behavior and evidence

## Read-only ArtifactViewer (D-194)

`@hachej/boring-ui-kit/artifact-viewer` presents host-supplied Markdown, HTML, images, PDF and text without a resource controller, editor or agent. This is host presentation, not a Pi execution extension. It shares HtmlViewer's passive allowlist, uses native browser PDF by default and owns only Blob URLs made from its content. The [UI guide](../../packages/ui/README.md#read-only-artifactviewer) owns props, precedence and limits.

`test/packages/ui-artifact-viewer.test.mjs` drives the built public entry with fictional DOM fixtures and audits its browser import graph. `npm run test:artifact-viewer-consumer` repeats that evidence from an isolated tarball with strict declarations and no files, controllers, Tiptap, canvas, pdfjs or agent dependency. Existing HtmlViewer tests protect the shared allowlist extraction. These tests do not qualify actual browser PDF support, CSP enforcement, inert parsing or egress. No registry wrapper, consumer migration, editing or global proof qualification is included.

## Floating utility windows (D-79)

The `windows` registry item is host presentation, independent of Pi: `WindowLayer`,
`FloatingWindow`, `WindowLauncher`, `useWindow` and the shared `useDraggable` hook.
Window rectangles and open/minimized/closed status are remembered in session or
local storage; desktop windows drag, resize and raise on pointer or keyboard focus.
Below 641px the front window uses the host's full-screen Drawer. The app shell
uses the same extracted drag hook without changing its dock/float contract.
See [the recipe](../../registry/README.md#floating-windows-windows).

`test/contracts/windows.test.mjs` drives public React/shadcn interactions, focus,
resize, persistence and breakpoint behavior; `windows.source.test.mjs` checks
strict types, the shared hook dependency and generated registry source.
`npm run windows:journey` drives fictional Notes, Calculatrice and Planning at
1440px and 390px, with screenshots under `.cache/evidence/D79/`. The existing
app-shell tests and journey remain unchanged. Browser layout is not document
persistence, real-device qualification or npm publication. Global deferrals remain.

## Requests board

The `requests-board` registry item is host presentation (no Pi extension): `RequestsBoard`, pure `compactRows`/`filterViews`/`requestCounts` and EN/FR labels. Compact prioritizes five requests; full mode provides scoped filters/search, responsive list/detail, history, related links and host-owned answer/decision/try callbacks. The host re-renders views and bumps a change token for polite announcements; the block never polls or subscribes. Release approval visibility is not authorization. See [the recipe](../../registry/README.md#requests-board-requests-board).

`test/contracts/requests.test.mjs` tests transforms; `test/contracts/requests-board.test.mjs` isolates real shadcn Happy DOM rendering and callbacks through `RequestsBoard`. `npm run requests:journey` drives the fictional `examples/workspace-app?requests` demo, including phone Back, keyboard, both languages, release gating and host-token updates, with light/dark screenshots under `.cache/evidence/D141/`. No backend, durable mutation, consumer D-140 integration or release qualification is claimed.

## Anchored Markdown highlights (D-78)

`@hachej/boring-ui-kit/markdown-quote` resolves `markdown.quote@1` literally over
canonical source. `@hachej/boring-ui-kit/mark-store` uses the document's workspace
client and existing conditional text buffer to save `<doc>.marks.json`.
The `highlights` registry block borrows the editor, decorates without text edits,
offers context actions/comments, and keeps missing/ambiguous marks in a candidate
tray. [FEEDBACK](../architecture/FEEDBACK.md#markdown-quotes-and-document-marks)
owns the semantics and conservative projection limits.

Evidence: `test/packages/ui-markdown-quote.test.mjs` runs the named exact-only
corpus through `runAnchorConformance`, including an offset-guesser negative
control; `test/packages/ui-mark-store.test.mjs` covers add/edit/remove, two-tab CAS,
lost replies, malformed sidecars, immutable capture and reentrant subscribers;
`test/contracts/highlights.test.mjs` drives the public registry block with real
React/Tiptap and SQLite. `test:document-consumer` includes headless marks and
quotes without React, plus strict declarations and a browser bundle. The actual
`highlights:journey` drives candidate persistence, comment editing, stale second-tab
refusal, source capture/removal and unchanged document bytes through HTTP.
Screenshots cover desktop/390px, FR/EN and light/dark under `.cache/evidence/D78/`.

No agent, D-76 conflict UI, general rich source map, real-device or production
identity-provider qualification is claimed. Existing global deferrals remain.

## Shared document readers

`@hachej/boring-agent/documents` adds optional native `read_pdf` and `read_spreadsheet` registrations and the `sniff`/`readStored` helpers. The [agent guide](../../packages/agent/README.md#shared-document-readers) owns their result shapes, limits and host callback contract. The Pi seam is `defineTool`; the stored-file helper returns native tool content without changing Pi's `read`.

`node --test test/packages/agent-documents.test.mjs` exercises public output through a real Harness: generated fictional PDFs, selected scanned-page OCR, missing/failed OCR, page/text caps, xlsx/xls/ods/CSV sheet/range limits, native image content, typed binary refusals, host read failures and lazy dependency imports. The complete-JSON regression fails under Pi's default 50 KiB output cap and passes with the readers' explicit native byte limit. These are local parser/native-tool tests, not live OCR/provider qualification or an input-memory/CPU budget. Global release deferrals are unchanged.

## Typed record viewer

The `record-viewer` registry item exports `RecordTable`, `RecordList`, `RecordsViewer` and `createRecordsKind` for `*.records.json` (`records@1`). This is host presentation, not a Pi execution extension. Tables group typed rows; app-provided status labels/tones select host Badge variants without domain interpretation. English/French labels and locale number/date formatting are supported. The file viewer uses a full-field list below 640px and exact raw-text fallback for invalid files. Host callbacks own row actions; absent handlers leave buttons disabled.

`test/contracts/record-viewer.test.mjs` drives the real ArtifactPanel, precedence, grouping, statuses, actions, localization and malformed input. `npm run records:journey` drives native write/present through the workspace app with 30 fictional workshop rows, desktop/phone actions, overflow checks and light/dark screenshots under `.cache/evidence/D77/`. [The registry guide](../../registry/README.md#typed-records-record-viewer) owns the data shape and composition examples. No live domain-service, real-model, npm publication or global proof qualification is claimed.

## Board artifact viewer

The `board-viewer` registry block exports `createBoardKind` for `*.board.json`. This is host presentation over the native tldraw renderer, not a Pi execution extension. `CanvasProjection` from the optional canvas-editor entry renders frames without a native-document publication controller. The existing text buffer conditionally saves only `board@1`; conflicts and uncertain acknowledgements retain local edits and the original operation identity. Maquette screens and sandboxed `MockupViewer` frames share the workspace client.

`test/contracts/board-viewer.test.mjs` drives the public artifact-kind entry, including invalid/newer files and failed linked reads. `npm run board:journey` drives the actual artifact panel, desktop pointer moves and panning, real provider revisions, lost acknowledgements, late saves, conflicts, external rewrites, pinned history and phone read-only input. Screenshots at 1440 and 390, light and dark, live under `.cache/evidence/feat-board-viewer/`. Structured board pin delivery, freehand record persistence and production host licensing/CSP remain separate qualifications.

## Document draft recovery

The four document controllers expose optional checkpoint, discover, restore and
discard actions. The [UI guide](../../packages/ui/README.md#opt-in-document-draft-recovery)
owns their usage. Tests exercise real SQLite drafts and publication receipts,
SIGKILL, session revocation, expiry, independent writers, dirty-buffer protection,
late acknowledgements and native canvas validation. Experience restore drops old
proposal and Pin authority. Chat recovery remains separate work.

Run `node --experimental-test-isolation=none --test test/packages/ui-text-drafts.test.mjs test/packages/ui-viewer-draft-recovery.test.mjs`
and `npm run test:document-consumer`. The installed consumer executes the core
suite from actual files/UI archives without Pi, agent or React. Browser and final
gate results remain in `.cache/evidence/draft-recovery/`; source or bundle checks
alone do not establish browser persistence. No global release proof is promoted.
