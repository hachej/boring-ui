# Packages

The npm side of the kit: Pi-based agent definitions and handlers, the workspace provider, execution adapters, headless UI controllers, feedback, and the CLI that installs and checks blocks.

## Sub-features

- `pkg-agent-action-context` optional lazy host context preparation on full-model fallback only; action extraction and automatic replies bypass it. `packages/agent/src/actions.ts`.
- `pkg-agent-actions` optional decision, structured extraction, native tool and result-derived reply, with native unavailable-model outcomes and deferred fallback polling/cancellation. `packages/agent/src/actions.ts`.

- `pkg-agent-define` `defineAgent`, tools, extensions, delegates. `packages/agent/src/agents.ts`.
- `pkg-agent-struggle` every `defineAgent` agent reports its own failures by default (S6): the `report_bug` tool and content-free `agent.struggle` events to the host's sink. `packages/agent/src/struggle.ts`.
- `pkg-agent-skills-unlisted` `skillInFolder` is public; `loadUnlisted(conversationId, name)` answers `load_skill` for a skill kept out of the listing. `packages/agent/src/skills.ts`.
- `pkg-agent-transport` chat transport and conversations handlers. `packages/agent/src/chat-transport.ts`, `conversations.ts`.
- `pkg-agent-capabilities` file guard, approvals, `ask_user`, `present`, schedules, sandbox. `packages/agent/src/file-guard.ts`, `approval.ts`, `ask-user.ts`, `artifacts.ts`, `schedule.ts`, `sandbox.ts`.
- `pkg-agent-audit` `createAuditExtension({ sink, user, redact })` (`@hachej/boring-agent/audit`): opt-in, sends each finished tool call to the host's store, attributed to the user; values only through `redact`. `packages/agent/src/audit.ts`.
- `pkg-agent-delegate-meter` delegate `onChild` and `meter` receive `{ callId, taskId, requestId }`; `meterFromSink` (`@hachej/boring-agent/metering`) feeds a child's spend to a `MeteringSink`. `packages/agent/src/delegate.ts`, `metering.ts`.
- `pkg-agent-context` request context and mention resolver. `packages/agent/src/prompt-context.ts`, `mentions.ts`.
- `pkg-agent-questions-delivery` optional native questions, validation and durable application-result delivery. `packages/agent/src/questions.ts`, `validation.ts`, `delivery.ts`.
- `pkg-agent-room-metering` shared-room entries, native usage metering and per-request context; host policy remains external. `packages/agent/src/room/`, `metering.ts`.
- `pkg-agent-runs` one-call runs: the result protocol (schema, validator, repair budget), the run ends and their delivery once, the outbox of starts, and the runner over a person's SQLite store. `packages/agent/src/run-result.ts`, `runs.ts`, `run-ledger.ts`, `run-outbox.ts`. Drive: `test/packages/agent-runs.test.mjs`.
- `pkg-files-workspace` one workspace provider, journal, SQLite, revision handler. `packages/files/src/workspace.ts`, `revision-handler.ts`.
- `pkg-files-sniff` a file's media type from its bytes; office documents whatever their zip entry order, from a head or the whole file. `packages/files/src/file-types.ts`.
- `pkg-execution` virtual bash and git, remote shell and files, AWS interpreter. `packages/execution/src/`.
- `pkg-execution-interpreter-nofollow` the AWS interpreter env's file operations walk the host's mount by directory fds with O_NOFOLLOW, so a directory the interpreter swaps for a link to outside the folder is refused, whatever the timing; links inside the folder still resolve where the operation follows links. Linux only (`/proc/self/fd`), fails closed elsewhere. `packages/execution/src/no-follow-fs.ts`. Drive: `node --test test/packages/execution-remote-symlink-race.test.mjs`.
- `pkg-ui-kit` headless controllers, editors and viewers, registry items under `r/`. `packages/ui/src/`.
- `pkg-ui-body-roles` ordinary SidebarMenuButton, Label/Field label, description/error, DropdownMenu item/checkbox/radio/submenu, TraceLine activity summary/count and ItemDescription hint roles use 12px; Card/Item titles remain 14px and mobile editable inputs retain 16px. TraceDescription uses unattenuated semantic muted foreground for enabled count contrast. `shadcn/ui/`, `registry/app-shell/account.tsx`.
- `pkg-ui-bundled-primitives` compact shared Button/Input/Select, flat Card, soft Badge/Alert statuses (every Alert variant has a 1px contour in its status colour) and consistent Tabs/Empty/Table typography. `shadcn/ui/` is consumed by Factory's bundle; ordinary npm blocks still borrow host primitives. A Button whose `render` has `href` or `to` is a link: `role="link"`, `nativeButton` false, no Space activation. Scope and qualifications: [bundled primitive defaults](../registry/README.md#bundled-primitive-defaults).
- `pkg-ui-status-contrast` enabled default/status Badge, AlertDescription and destructive Button copy use existing contrasting semantic ink without removing soft fills or disabled-state distinctions. `shadcn/ui/badge.tsx`, `alert.tsx`, `button.tsx`.
- `pkg-ui-chat-body` Message/Bubble/Attachment and InputGroup copy default to 12px; Textarea (including Composer's InputGroupTextarea) uses 12px on desktop and the existing 16px mobile input exception. Semantic app titles remain 14px. `shadcn/ui/message.tsx`, `bubble.tsx`, `attachment.tsx`, `input-group.tsx`, `textarea.tsx`.
- `pkg-ui-default-icons` real pinned Phosphor defaults through the existing fixed `registry/_shared/icons.ts` map for registry blocks and bundled primitives; native SVG refs/props and existing host icon customization remain. Its explicit client boundary isolates Phosphor's React context for RSC hosts without marking surrounding KPI/empty-state blocks client-only. Package-owned Library/Markdown defaults and Factory provisioning are explicitly separate: [default icons](../registry/README.md#default-icons).
- `pkg-ui-default-theme` optional original-reference canvas/card, base radius, 12/14 type roles, font-family declarations, soft semantic statuses and mode-tuned five-slot categorical defaults aligned with Factory; explicit branded overrides and opt-in installation remain unchanged. `registry.json` owns the `theme` item; `public/r/theme.json` is the generated installation output. Required host/bundle adoption is tracked in [the registry guide](../registry/README.md#default-theme-foundations).
- `pkg-ui-markdown-labels` Markdown editor English/French text and per-key `labels` overrides, including accessible names, proposal diff, preserved blocks and recovery controls; source textarea placeholders. `packages/ui/src/markdown-editor-labels.ts`, `markdown-editor.tsx`.
- `pkg-ui-markdown-conflict-choices` a refused save or a known newer revision shows Keep mine (rebase onto the revision shown, then the same conditional write; a remote that moved again is a new conflict), Take theirs (`discardToRemote`) and Review diff (the newest saved text against the local text; only what the editor knows of the remote moves, so Keep mine acts on what was shown). `packages/ui/src/markdown-conflict-choices.tsx`, `text-buffer.ts`.
- `pkg-ui-markdown-receipt` the saved revision under the header after each save, also with `header={false}`. `packages/ui/src/markdown-editor.tsx`.
- `pkg-ui-markdown-tab-poke` optional BroadcastChannel poke, `crossTabRefresh`: a saved revision goes out, other tabs of the note run their existing refresh; no text on the channel, a refresh never pokes back, a missing or broken channel does nothing. `packages/ui/src/markdown-tab-poke.ts`.
- `pkg-ui-markdown-size-limit` a note over `richSizeLimit` bytes (default 512 KiB) opens as source with a visible reason, cannot switch to rich mode and is not parsed behind the source box. `packages/ui/src/markdown-safety.ts`.
- `pkg-ui-voice-capture` public PCM capture progress, actual input level and pause/resume; paused frames never enter the WAV. `packages/ui/src/voice-capture.ts`.
- `pkg-ui-experiences` fixed and generated experience composition with typed cells and conditional keep/pin. `packages/ui/src/experience*`.
- `pkg-ui-remote-chat` authorized remote chat projections and client controller. `packages/ui/src/remote-chat.ts`, `packages/agent/src/projection.ts`.
- `pkg-browser-worker` opt-in browser worker transport, SQLite, model setup and unchanged native code mode. `packages/browser/src/`; package is private to this repository.
- `pkg-testing-tools` keyless scripted model and headless browser/network helpers. `packages/testing/src/`; test tooling only.
- `pkg-chat-react` opt-in view selectors, transcript windows/chunks, drafts, placement, remote and conversations hooks; per-selection adapter ownership preserves concrete APIs. `packages/ui/src/chat-react.ts`, `chat-react-*.ts`.
- `pkg-blocks-cli` `boring-ui-blocks add | update | check | manifest`. `packages/ui/bin/boring-ui-blocks.mjs`. `add` and `update` refuse a symlinked `node_modules` or scope directory (a borrowed install); `check` still works there. Driven by `test/packages/ui-blocks-add.test.mjs`.
- `pkg-ui-textarea-code` `<Textarea variant="code" />`: the kit's one monospace field for source text and pasted payloads (D-1782): `font-mono`, no ligatures (`font-variant-ligatures: none`), tab width 2, theme tokens only. `shadcn/ui/textarea.tsx`, `test/ui/textarea-code.test.mjs`.
- `pkg-blocks-design` `boring-ui-blocks design <dir> [--changed <file>...] [--json]`: the one design check of an app's `web/src`, run by every Boring app and by Factory's verify (D-1789). Needs no `components.json` and no copied shadcn files. Ports the Factory template's rules by id (`raw-element`, `kit-block`, `line-length`, `component-length`, `file-length`, `design-card-flat`, `design-icons-phosphor`, `design-touch-target`, `design-button-raw-height`, `design-no-dark-overrides`, `design-link-token`, `design-mono-for-code`), the kit's `check --design` app profile (`design-color`, `design-border-width`, `design-font-tokens`, `design-literal-value`, `design-dark-variant`, `design-no-x-scroll`) and the new `design-tokens-only` (arbitrary values; `var(--x)` and `grid-cols`, `grid-rows`, `auto-cols`, `auto-rows`, `aspect`, `z`, `order`, `col`, `row`, `columns`, `content`, `will-change` allowed), `design-no-kit-restyle`, `design-no-important`, `design-no-script-tokens` (`setProperty("--sidebar-width"`, also `-icon` and `-mobile`, in app script: the theme owns the width and `AppShell resizable` lets the person change it; D-1898), `design-hand-touch-size`, `design-theme-core-only` (theme.core.css does not set a name the kit derives, `KIT_DERIVED`, above its `=== EXCEPTIONS ===` comment; core roles and the app's own tokens such as `--pm-*` or `--shadow-halo` are fine; a token pinned below the comment needs a `` `--name` `` entry under `exceptions:` in the root `DESIGN.md`, and missing entries are one hit for the block; theme.derived.css is not read by this rule: an app that has one gets the single `design-theme-local-derived`), `design-theme-roles-both-modes` (a kit-defined colour name, a core role or a `KIT_DERIVED` name pinned below the comment, in `:root` and not `.dark`, or the reverse; an app's own token such as `--cta` or `--overlay` may be mode-independent and is never a hit; a one-mode pin whose every `var()` follows, along the chain, to a both-modes token or a core role passes, a literal, a `:root`-only token, a missing token or a cycle does not) and `design-overlay-has-title` (a Dialog, Sheet, AlertDialog or Drawer content without its `*Title`; a `{body}` child bound by `const`/`let` or `function` in the same file is searched for the Title). Only the files inside `<root>/components/ui` are the legacy exemption (an empty folder downgrades nothing else); a colour or `dark:` in a plain string or prose is not a hit, only in a class or a colour property, dot folders are scanned as the template does, links are not followed, and a fatal error is `{"error":...}` with exit 1. `design-no-kit-restyle` matches only the kit's own `data-slot` values (`KIT_SLOTS`, kept equal to shadcn/ui and the registry by a test); `design-tokens-only` reads class contexts only (`className`, `class`, `cn()`, `cva()`, `clsx()`, `tw`). One level table, `LEVELS`: every rule is an error, frozen by design-master after a false-positive read (no warn tier; `level` stays in the JSON; a colour literal counts only in a class or a colour property, not in a code sample, user text, a test file or `url(#id)`). `design-theme-local-derived`: one hit per app that has its own `theme.derived.css` (delete it, import the kit's). Exception list that only shrinks (`pkg-blocks-design-exceptions`): `design.exceptions.json` in the scanned directory or `--exceptions <file>`, `{"<rule>": {"<file>": <count>}}`; hits up to the count are `excepted: true` and do not fail, others fail; a stale count, rule or file is `design-exceptions-shrink` ("N hits left, lower the list to N"); `--baseline` prints the list for the current hits and writes nothing (the Factory gate refuses a PR that grows it). `test/design-exceptions.test.mjs`. `packages/ui/bin/boring-ui-blocks.mjs`, `test/design-app.test.mjs`.
- `pkg-feedback` in-app feedback capture and delivery. `packages/feedback/src/`.

## How to get to it (user POV)

- A developer or an agent installs `@hachej/boring-*` packages and runs `npx boring-ui-blocks` in the app's web directory.

## Gotchas

- Keep every `@hachej/boring-*` package on one version; Pi packages are peers at `~1.4.0`.
- The host owns the Harness, policy and credentials; kit packages never open a Harness.
- Change `ARCHITECTURE.json` before a new package or edge.
- Explicit `theme.json` installation overwrites matching host variables. Blocks never install it automatically. Factory template/bundle adoption, full mira catalogue qualification, unnested composition, actual host Geist loading, full Phosphor coverage/adoption and a global 14px app ceiling remain separate work; the bounded shared primitive unit supplies flat Cards/compact controls, not host installation or full convergence. Family declarations alone do not load fonts. Ordinary block installation preserving branded tokens is structurally checked here, not installer-qualified by the focused theme test.

The opt-in kit `chat-react` entry also owns `useChatSession` (state/files/send/restore/queue/upload/paste/model-effort); the root stays free of files/Pi/agent imports. Drive `node --test test/packages/ui-chat-session.test.mjs` and `npm run test:pi-chat-consumer`; see [chat-session](chat.md).
