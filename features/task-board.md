# Task board

Host-owned business requests rendered from authorized records, shared by a board, its detail and compact own-request rows. No task backend, Pi scheduler or PM conversation is created by the component.

## Sub-features

- `task-uncut-title` compact cards use the host's authored concise `display`, otherwise the complete original title. They normalize whitespace but never cut either sentence at a word count. Hosts author/backfill meaningful localized display titles of six words or fewer; original title/spec remain untouched. `registry/task-board/compact-presentation.ts`.
- `task-display-title` cards prefer the host's localized `display` while retaining the original `title` for expanded details. `TaskRecord.technical` carries explicit host classification, never inferred from prose or actor names. Neither field changes authorization or ownership. `packages/ui/src/task-board.ts`, `registry/task-board/task-request-card.tsx`.

- `task-board-status` operator viewer/builder/high-risk/none semantics (the standalone `TaskStatusPill` also supports opt-in `sent` for a confirmed open request) and EN/FR labels; `TaskStatusPill` renders one pill per task from the theme's primary/secondary/destructive roles (French viewer pill: the host's warning-soft role). `packages/ui/src/task-board.ts`, `registry/task-board/task-request-card.tsx`.
- `task-board-columns` one board consumed everywhere: columns by who acts next (Needs you, Blocked, In progress, Recently live for a week), Finished and Technical folded. The panel's own width decides: side by side from a 3xl container, stacked below with empty sections hidden, so a PM panel or phone gets the same component. A card shows the title, then the question, the block reason or one status. `registry/task-board/task-board.tsx`, `registry/task-board/compact-presentation.ts`.
- `task-board-reason` a request that needs the viewer or is blocked always says so in its detail: the open question with options or a direct answer field, otherwise the projected reason and where to reply. `registry/task-board/task-detail.tsx`.
- `task-board-apps` a host showing several apps sets `TaskRecord.app`: cards name the app and the bar filters by it. No filter with one app. `registry/task-board/task-board.tsx`.
- `task-board-bar-start` optional `barStart` content at the start of the tasks bar (the collapsed Studio header's app name and « Show the app »). `registry/task-board/task-board.tsx`.
- `task-board-detail` URL selection with back/forward and keyboard Back/Escape; a 400px panel-scoped overlay (absolute, right, below the tasks bar) over the unchanged board: 40px header « ‹ », `D-201 · 12m`, pill; then title card (« Screen: … · asked by … · refined by … »), QUESTION FOR YOU, ANSWERED, FILES, « Ask in the conversation ». Host-owned overlayClassName appearance. `registry/task-board/task-board.tsx`, `registry/task-board/task-detail.tsx`.
- `task-board-answers` the first open question waiting on the viewer (QUESTION FOR YOU, `askedBy · askedAt`, first option primary, Other… opens an inline field whose Send passes the typed text, Discuss in chat) precedes ANSWERED · N: latest three as two-line rows (question ›, `Who: answer`), row click expands the full text, Show all. Optional answeredAt sorts newest first; otherwise latest source entries first. Discuss is a separate injected callback, never invoked by a one-tap answer. The example stages that question in the existing draft; only Send submits it. `onAsk` backs « Ask in the conversation ». `registry/task-board/task-detail.tsx`, `packages/ui/src/task-board.ts`.
- `task-board-files` FILES · <folder>/ rows (file / browser-frame / image icon, path relative to the folder, Markdown / Mockup / Capture); a row opens `renderFile` in a 760px panel-scoped overlay over the task; Back/Escape navigate file → task → unchanged board. The host supplies its regular viewer and optional `onOpenFile` / `onShowFile` services. `registry/task-board/task-board.tsx`.
- `task-board-mentions` optional task-mentions registry adapter composes authorized ID/title search and waiting markers with the host's file search/kinds, using the existing MentionPicker and composer; a task-kind sent chip opens the same overlay. `registry/task-mentions/task-mentions.tsx`.
- `task-board-native-present` one real native Pi Harness and AmbientChat host task/list presentation; actual loaded mount, cleanup and denied/missing reports, no dummy task file. `examples/task-board/server.mjs`, `examples/task-board/page.tsx`.
- `task-board-mine` own requests, newest first within priority, filtered before `limit`; `variant="compact"` puts current needs-you first, hides canonical technical records, and collapses closed records. `compactPresentation.includeTechnical: true` adds a collapsed technical group for already-authorized records, never server rights. Opens through the host's shared detail path. `packages/ui/src/task-board.ts`, `registry/task-board/task-board.tsx`.
- `task-compact-presentation` the typed `compactPresentation.includeTechnical` prop opts into a collapsed group of already-authorized canonical technical records; omitted by default. UI-only, never server rights. `registry/task-board/task-board.tsx`.
- `task-request-card` one record, two renderings: unchanged operator board card (D2) and title-first compact row (preferred authored `display`, otherwise complete original title; no blind sentence cutting), exactly one localized product chip, no repeated REQUEST/DEMANDE, reference, screen/capture or actor metadata. Terminal closed/withdrawn guards stale flags; done/shipped is live; then strictly waiting + `waiting_on_you === true`, blocked, verifying, preparation. Only exact machine `status` tokens are used (`abandoned`/`withdrawn`, `closed`, `shipped`, `blocked`, `verifying`), never prose. `pill` replaces that one chip (host supplies one), preserving PM closed-reason wording; `viewerAction` retains confirmation wording and authorized actions stay injected. Original title/spec/record stay untouched for `onOpen` and detail. `registry/task-board/task-request-card.tsx`, `registry/task-board/compact-presentation.ts`.
- `task-board-compare` board-by-board screenshots at the mockup viewport beside the exported mockups. `examples/task-board/compare.mjs`.

## How to get to it (user POV)

- Open the fictional task-board example (Coach Max data); one native Ambient PM conversation sits left, the tasks panel right. `?layout=ambient` collapses the conversation to the ambient composer; `?view=compact` shows the French C7 card and « Mes demandes » at phone width.
- Ask « What's waiting on me? » or select a task; « ‹ » (Back to the tasks) or Escape returns to the originating card. Open a file to stack the wider regular viewer over that task; Back returns through the preserved task state.

## Gotchas

- Blocks pick no radius, border, shadow or colour literal (BORING-UI-1). Spec sizes come from host tokens the block reads (`taskTokens`): `--task-pill-height` / `--task-pill-font-size`, `--task-control-height`, `--task-column-radius`, `--task-card-padding-y` / `-x`. Without them the stock shadcn values apply; Studio's theme (the fixture's `studio-theme.css`) sets the spec values, Coach Max keeps its own theme. `compare.mjs` fails if D2 does not measure 11px/17px pills, 34px controls, 12px columns, 9/11 card padding and a 400px overlay.
- Hosts authorize and adapt records before rendering. `filter: 'mine'` is not authorization; the adapter supplies `requesterId`, never inferred from the assignee. Missing `currentUser` matches no own requests.
- Question/action callbacks are host intents, not approval, persistence or confirmed execution. Text remains escaped; captures are labels, not arbitrary remote image URLs.
- Files, answer identities and permissions belong to the adapter. The example resource route permits only the three supplied D-201 paths. `renderFile` borrows the host viewer; fullscreen/comments/pointing are that viewer/host's services, not TaskBoard implementations. The fixture records Montrer intent only: no PM point capture/chip, comment storage or second composer.
- Compact lists require the host `onOpen` detail/present route; their existing compact rendering does not mount a local detail. The operator board remains the native default URL/detail host.
- Default selection uses the page's `task` query parameter. Multiple boards should use controlled selection or `onOpen` to route to one detail; with `onOpen`, the component does not also open a local detail. Unmount only removes presentation subscriptions.
