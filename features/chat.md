# Chat

`pi-chat` is the conversation: transcript, composer, tool steps and reply cards, over a `NativeChatController`. Optional items add composer features and cards; each is absent without its item and its prop.

## Sub-features

- `chat-transcript` rows, tool steps, activity, Markdown replies (`pi-chat-markdown`), `presentation="natural"` for readers. Paging/chunks live in `packages/ui/src/chat-react-transcript.ts`; `registry/pi-chat/session.tsx` adapts the host's shadcn MessageScroller. Rendering: `registry/pi-chat/pi-chat.tsx`, `rows.ts`, `message.tsx`.
- `chat-tool-details` `toolDetails="none"` for readers who are not technical: a tool step never shows arguments, result or error text, a failed step stays closed and reads `labels.toolFailedSummary` right under its line, a failed activity's header names no tool (`labels.activityFailedPlain`); `'auto'` (default) is unchanged. `registry/pi-chat/tool.tsx`, `activity.tsx`, `message.tsx`; prop in `session.tsx`.
- `chat-tool-row` one spinner per screen: a running step row (`activity`) shows a small muted pulsing dot (`activity-dot`, `animate-pulse`, static under `motion-reduce`), a finished one no dot, and the "Agent is working" line keeps the only spinner. `hideTools` (default false) renders no step rows while running or after; approvals, questions, sub-agent cards, artifacts and a failed step still show. `registry/pi-chat/activity.tsx`, `message.tsx`, `session.tsx`.
- `chat-session` headless state/files, connect/errors, send/restore, queue, uploads/paste and model/effort reconciliation, preserving existing app-kind send recovery and hidden-token paste coordinates. `packages/ui/src/chat-react-session.ts`; `registry/pi-chat/session.tsx` builds JSX/context/composer props only. Old contract imports remain re-exports for one release.
- `chat-connection-status` reusable `ChatConnectionNotice` / `ChatStatusLine` in `registry/pi-chat/notice.tsx`; PiChat and Ambient retain host connection recovery and identical developer/natural status choices. Compact Ambient keeps `loadFailedShort`/`disconnectedShort` overrides unless the host error renderer is supplied.
- `chat-jump-latest` scrolled up, the down arrow sits in its own row under the messages; at the latest message the row is gone, so no empty band sits above the composer (D-1403). `registry/pi-chat/pi-chat.tsx`.
- `chat-composer` multi-line composer, including sizing/width observation after recording trash, queue (steer, edit, remove), draft kept per conversation (`useChatDraft`, `packages/ui/src/chat-react-draft.ts`). `registry/pi-chat/composer.tsx`, `queue.tsx`.
- `chat-header-more` the pi-chat header "…" overflow trigger is a bold 20px glyph (`size-5`; dots at least 2.2px) in its 24px button, 44px on touch, while the reply row keeps 16px (`BlockActions moreWeight`, `moreIconClassName`; D-1905).
- `chat-text-size` the assistant reads at `--text-chat` (default 0.9375rem, line-height 1.6, at least 1rem on touch; D-1901): prose, Markdown, composer, empty state, cards and the panel title follow it; meta rows (thought, tool, time, actions) are 0.93 of it in muted ink; code is 0.875 of it. An app sets it in its `theme.core.css`. Rules in `packages/ui/styles/app.css` (a kit bump delivers them); the portalled menus (composer, picker, queue, header and reply overflow via `BlockActions menuClassName`) and camera carry the `pi-chat` class.

Inside `AppShell` the shell's `locale` wins over `chatProps.locale`; a bare `PiChat` follows its own `locale`.

A failed connect never sends them: the state turns `offline` and they come back in the next attempt's composer. `packages/ui/src/chat-react-remote.ts`, `chat-react-controller.ts`, `native-chat.ts` (`send`), `chat-react-session.ts`.

- `chat-photo-links` a photo sent as a link (`{ type: 'image', data: '', url }`, the url relative to the chat endpoint) is drawn from that link in the message, the viewer and the artifact panel, in the live view and in earlier pages (the replica keeps the host's link; the resolved copy is derived after each replay); only http(s) links draw, and a missing or broken one shows a placeholder, never a broken image (D-1433). `packages/ui/src/remote-chat.ts`, `registry/pi-chat/composer.tsx` (`imageSource`), `message.tsx`, `image-viewer.tsx`.
- `chat-idle-poll` `useConversationsClient({ idlePollMs = 30000, pollMs = 4000, busy })`: the list refreshes every `idlePollMs` while visible and idle, every `pollMs` while `busy` (and `PiChat` reloads every 4 s while its turn runs, and once at its end, on one clock: none when the host's `conversations.polling` is set, which the hook sets with `busy`; `registry/pi-chat/pi-chat.tsx`), never while the tab is hidden, and once on return (visibilitychange and focus together are one request; a focus after a blur that never hid the page still refreshes) and at turn end (D-1638). `packages/ui/src/chat-react-conversations.ts`. Drive: `node --test test/ui/conversations-idle-poll.test.mjs test/ui/pi-chat-conversations-reload.test.mjs`.
- `chat-served-end` the host's `session_closed` end frame on an `op=watch` stream is drained to its close, not cancelled or aborted (no ERR_ABORTED), the watch reopens, and one stream is open at a time; hiding the page or disposing the chat during that drain aborts it at once (D-1638). `packages/ui/src/remote-chat.ts`. Drive: `node --test test/packages/ui-remote-chat-served-end.test.mjs`.
- `chat-reconnect` the same controller keeps sending after the connection drops and returns (the host restarted). When the stream is back with a complete view, a send that was waiting on the lost connection is settled against the host's record of its request ID: unconfirmed (`send.kind` `unknown`) is checked and, if the host never had it, sent again with the same request ID; confirmed (`admitted`) but missing from the returned view and unknown to the host (it lost the turn) is sent again the same way; if the host has the turn nothing is sent, so the turn appears once. The typed draft stays in the composer, and messages sent meanwhile wait behind it, in order. A message sent while the stream is being reopened (`connection.kind` `reconnecting`) is no longer refused with its text left in the field: the composer takes it, the controller holds it (shown as the person's own, as while the chat connects), asks the transport to reopen the stream now (`ChatLink.reconnectNow`, so the backoff does not delay it), settles the send that was waiting first, then submits it once the connection is back; if the connection fails it returns to the composer. Nothing happens for a drop while idle. A host still away leaves the send as it was, with the Check / Retry notice. A submission handle's `wait()` over the remote client asks again after the host was away (no connection, 5xx, 408, 429) instead of failing with it, and ends only when settled, aborted, or the host says it has no such submission. `packages/ui/src/native-chat.ts` (`recover`, `dispatch`), `packages/ui/src/chat-react-session.ts` (`sendBlocked`), `packages/ui/src/remote-chat.ts`. Drive: `node --test test/packages/ui-native-chat-reconnect.test.mjs`.
- `chat-first-view-timeout` `createRemoteChat({ firstViewTimeoutMs })` (default 18000): a host that never sends the first view is an error with retry, not « Connexion… » for good. `packages/ui/src/remote-chat.ts`.
- `chat-projected-watch` with the transport's `project`, a watch sends the first projected view, then the operation batch between projected views (`diffRevisions`; the client replays it as it does native operations), so an update costs the same whatever the conversation holds: 62 KB per update became about 0.1 KB at 40 earlier turns, and the replica's unchanged entries keep their identity. A batch that is not under half the full view's size falls back to the full view. Raw operations never leave the host. `packages/agent/src/chat-transport.ts` (`frameEncoder`).
- `chat-plugins` `withChatPlugins(props)` fills every missing component and card. `registry/pi-chat-plugins/chat-plugins.ts`.
- `chat-resolve-link` `PiChat resolveLink(href, { source, text, title })` (also `AgentWorkspace chat`, `AgentChat chatProps`, `Markdown`, `markdownText`): the host's say over every link of a Markdown reply. Answers: an address (string), `{ href?, target?: '_blank' | '_self', onClick?(event, context) }`, `null` (the words, no link) or `undefined` (default: a plain http(s) link). Every result still passes the renderer's check (http(s), no credentials; `javascript:`, `data:`, `vbscript:` and relative addresses show as text), `rel="noopener noreferrer"` stays, a throwing resolver falls back to the default. `{ onClick }` without `href` draws a `<button type="button">` styled like the link (an in-app action: no address to copy or open in a tab); neither `href` nor `onClick` is words only; a refused `href` is words only even with an `onClick`; `onClick` gets the event and the link's context and its throw is not caught (it reaches the host's error reporting). `source` is `chat` here. `registry/pi-chat-markdown/markdown.tsx`, `registry/pi-chat/session.tsx`, `config.ts`.

- `chat-history-retry` native older-page reads time out after 15 seconds, retain the prior page and permit retry; late results cannot replace accepted history. New native threads without a head boundary do not advertise nonexistent older records. Pages start below the view's first entry, so the first page never repeats what is on screen; a host view's `hasEarlier` (read with `viewHasEarlier`) shows or hides « earlier » and `false` ends it without a scan (D-1433). `packages/ui/src/native-chat.ts`, `registry/pi-chat/pi-chat.tsx`.

## Gotchas

- A composer feature with no `Picker`/`Button` component renders nothing; install the item.
- Visual values are tokens only; `boring-ui-blocks check --design src` fails literals.
- `natural` presentation changes rendering only, never the stored history.
- `toolDetails="none"` changes rendering only. It wins over `mode="developer"` (as `natural` does); only the kit's `?chatMode=developer` switch brings the details back. It does not touch the response-error notice (use `replyError`) or reasoning steps.
- `hideTools` changes rendering only: the controller, the stored history and the working line are untouched. `?chatMode=developer` replaces it.
