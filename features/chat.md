# Chat

`pi-chat` is the conversation: transcript, composer, tool steps and reply cards, over a `NativeChatController`. Optional items add composer features and cards; each is absent without its item and its prop.

## Sub-features

- `chat-transcript` rows, tool steps, activity, Markdown replies (`pi-chat-markdown`), `presentation="natural"` for readers. Paging/chunks live in `packages/ui/src/chat-react-transcript.ts`; `registry/pi-chat/session.tsx` adapts the host's shadcn MessageScroller. Rendering: `registry/pi-chat/pi-chat.tsx`, `rows.ts`, `message.tsx`.
- `chat-session` headless state/files, connect/errors, send/restore, queue, uploads/paste and model/effort reconciliation, preserving existing app-kind send recovery and hidden-token paste coordinates. `packages/ui/src/chat-react-session.ts`; `registry/pi-chat/session.tsx` builds JSX/context/composer props only. Old contract imports remain re-exports for one release.
- `chat-connection-status` reusable `ChatConnectionNotice` / `ChatStatusLine` in `registry/pi-chat/notice.tsx`; PiChat and Ambient retain host connection recovery and identical developer/natural status choices. Compact Ambient keeps `loadFailedShort`/`disconnectedShort` overrides unless the host error renderer is supplied.
- `chat-jump-latest` scrolled up, the down arrow sits in its own row under the messages; at the latest message the row is gone, so no empty band sits above the composer (D-1403). `registry/pi-chat/pi-chat.tsx`.
- `chat-composer` multi-line composer, including sizing/width observation after recording trash, queue (steer, edit, remove), draft kept per conversation (`useChatDraft`, `packages/ui/src/chat-react-draft.ts`). `registry/pi-chat/composer.tsx`, `queue.tsx`.
- `chat-slash` the `/` menu: commands and skills. `registry/pi-chat-slash/slash-menu.tsx`.
- `chat-mentions` the `@` menu for files and, through `MentionsConfig`, any catalog of ids. `registry/pi-chat-mentions/mention-menu.tsx`, `registry/pi-chat/config.ts`.
- `chat-attachments` attach, paste, drop, paste-to-file, phone camera sheet. `registry/pi-chat-attachments/camera-sheet.tsx`.
- `chat-voice` tap-to-record with one replacement composer row: trash, timer, input waveform and Send. Presentation: `registry/pi-chat-voice/`; attempt ownership, dictation and retained-message preparation: `packages/ui/src/voice-attempt.ts`, `chat-dictation.ts`, `chat-voice-message.ts` through the opt-in `chat-react` entry.
- `chat-voice-lifecycle` one shared capture owner fences late permission/transcription, committed target changes and unmount; configurable dictation `maxMs` caps captured audio without sending automatically. `packages/ui/src/voice-attempt.ts`, `chat-dictation.ts`.
- `chat-voice-pause` pause/resume excludes paused PCM samples and freezes the timer; waveform bars advance only with captured samples and stop at the cap; unavailable capabilities are omitted on fallback recorders. `packages/ui/src/voice-capture.ts`.
- `chat-target-chip` a sent message that starts with a `<target>` block (point-and-speak) shows a chip and the speech; no raw target value shows anywhere (chip text, hover, accessibility tree, queued and sending rows, the conversation list's titles and tooltip; automatic titles and previews in `packages/agent/src/conversations.ts` drop the block). The chip reads the target's `label`, else the display keys it wraps its fields under, else « Target »; `targetLabel(target)` on PiChat, AmbientChat and SharedChat picks its words without changing the block's JSON. `registry/pi-chat/message.tsx`, `queue.tsx`, `history.tsx`, `registry/shared-chat/timeline.tsx`, `packages/ui/src/chat-view.ts` (`targetContent`).
- `chat-voice-replay` sent voice is transcript-only by default; explicit `voiceReplay` opts into the retained player without changing stored audio. `registry/pi-chat/message.tsx`.
- `chat-voice-untranscribed` audio-only recovery shows a localized non-playback missing-transcript status, including retained messages after reload. `registry/pi-chat/message.tsx`, `labels.ts`, `labels-fr.ts`.
- `chat-kind-skill` a registered leading `/skill` stays first in native submissions ahead of hidden app tokens, including unfinished quoted input. `packages/ui/src/chat-text.ts`, `registry/pi-chat/composer.tsx`.
- `chat-kind-mentions` registered app kinds show readable removable chips, hide their tokens from editable text and retain them in native submissions; sent kind/file mentions share text-line alignment. `registry/pi-chat/composer.tsx`, `packages/ui/src/chat-text.ts`.
- `chat-developer-switch` `?chatMode=developer` turns developer mode on in this browser, no code change, until `?chatMode=expert`. `registry/pi-chat/pi-chat.tsx`.
- `chat-recovered-step` a failed step the agent got past (a later step finished or something else came, and the reply ended normally) is not red and not opened for a person, and still opens by hand; a run that ends on the failure says so; developer mode stays red. `registry/pi-chat/message.tsx`.
- `chat-question-send` while a question waits, text typed in the composer makes the primary button Send and answers it (a picture follows as its own message; a question that cannot take it, options only, too long or not started, is superseded by stopping the run and sending; one answered elsewhere, or a second message, leaves an ordinary message; pending feedback waits for the next message); nothing typed, it stays Stop. `presentation="natural"` drops a failed question and a call with no question text yet, and the card never shows `<harness>` text. `packages/ui/src/chat-react-session.ts`, `packages/ui/src/chat-view.ts`, `registry/pi-chat-question/question-card.tsx`.
- `chat-answered-by` `mode="developer"`: one muted line under each assistant reply, « answered by provider/model » from the host's per-turn `answeredBy` (PiChat prop), else the reply's own message provider/model, plus « fallback: reason » when `answeredBy.fallback` is set; nothing without model info, never on user messages, unchanged in expert mode (D-1222). `registry/pi-chat/message.tsx`, `labels.ts`, `labels-fr.ts`.
- `chat-pickers` model and effort menus. `registry/pi-chat-pickers/pickers.tsx`.
- `chat-cards` question (`ask_user`), approval, sub-agent and artifact cards. A single waiting question renders through `InlineQuestion` (`registry/inline-question/`), the same component as the Factory home: a flat soft warning tint, one-tap choices (up to 6) and free text; a form of several questions keeps its own flat tinted layout, and an approval is a muted row. Test ids (`question-card`, `question-text`, `question-option`, `question-input`, `question-submit`, `question-refusal`) and answers are unchanged. The status paragraph (`StatusNarrative`) is a host slot: pass it through `timeline` or `belowComposer`; it needs the host's text, so the chat never builds it. `registry/pi-chat-question/`, `pi-chat-approval/`, `pi-chat-subagent/`, `pi-artifacts/`.
- `chat-conversations` History with New, rename, archive, fork over the host's conversations handler (`useConversationsClient`). `packages/ui/src/chat-react-conversations.ts`, `registry/pi-chat/history.tsx`; old hook imports re-export for one release.
- `chat-list-wheel` the wheel over the conversation list never moves what is behind it, at the list's ends or when the list is too short to scroll (`overscroll-contain` on its viewport).
- `chat-list-scroll` a long conversation list scrolls inside whatever holds it, including a popover or sheet with only a max-height (the workspace bar's History and `ConversationHistory`, on a computer and a phone): no row is drawn or takes a click outside the sheet or over the message box, the last row can be reached, and a short list draws as before (D-1528). The workspace bar's sheet stops at `min(30rem, 70dvh)`, which clears a centred message box at 1400x900; on a shorter window the box can still sit under it. `registry/pi-chat/history.tsx`, `registry/pi-app/workspace-bar.tsx`.
- `chat-search-failed` a History search that is refused or fails (400, 5xx, no network, an unreadable answer, also with the Archived filter) says so in the sheet with `labels.searchFailed` (`role="alert"`, French included) and draws no rows; « No conversation matches » stays for a search that answered empty. The next query clears it and runs again, and an aborted or replaced search shows nothing. The server's reason is not shown: the client keeps only the status (D-1562). `registry/pi-chat/history.tsx`, `registry/pi-chat/labels.ts`.
- `chat-new-dead-key` a dead key or IME composition still open as the new conversation opens finishes in the hidden field, and the committed text then goes in the box (`opened` stays undefined until `compositionend` or the field losing the focus), so no stray accent lands.
- `chat-new-first-message` from New or fork until the new conversation is selected (after the list reload and the host's `onChange`), `conversations.creating` holds the composer, voice button and suggestions in `PiChat` and the composer in `AmbientChat`, so a first message never goes to the conversation being left. Stop on a running reply still works (the composer's `stopOpen`). A list answer older than one already shown is dropped, so a late poll cannot take the new conversation back. Once the new conversation opens, the cursor goes to its box on a computer (`conversations.opened`), unless the person moved to another field, so typing works. `opened` lasts up to 3 s, for a box that comes back late, and ends once the cursor is placed (`openedSeen`), so a remount takes nothing. New takes the focus off the clicked button, so a Space typed then makes no other conversation, and on a computer into a hidden field (`new-chat-typing`) whose text goes in the new box once it is back and its controller is on that conversation (`openedSeen` returns it, in `PiChat` and `AmbientChat`), so the start of a message is not lost. Enter there sends nothing. A refused create, 15 s or picking a conversation drops that text, so the draft being left is never written. The focus does not go back to the button, where a Space would press New again. A refused New, an answer with no conversation or 15 s with no answer shows `new-chat-failed` above the box (`conversations.newFailed`, `PiChat` and `AmbientChat`): the conversation wasn't made and, if the person typed, the text wasn't kept. It goes on the next New, a picked conversation or its Close button, and belongs to the conversation the person stayed in. A create answered after the person stopped waiting is deleted, so no empty row stays, unless they have had it open here, it has a message (another tab), or the host changed list. A host refresh (`onChange`) that fails after a create that worked still opens the conversation. A second New does nothing while one is on its way. A refused create, 15 s without an answer (`openTimeoutMs`), another endpoint or picking a conversation gives the composer back, and a late answer moves nobody. `packages/ui/src/chat-react-conversations.ts`, `registry/pi-chat/pi-chat.tsx`, `registry/pi-ambient/ambient.tsx`.
- `chat-remote` `useRemoteChat` connects a concrete controller to the host's chat transport, with `requestContext` and placement. `packages/ui/src/chat-react-remote.ts`, `chat-react-controller.ts`; old hook imports re-export for one release.
- `chat-send-echo` the message the person sends is on screen at once (the controller's `echo`, drawn as their own message, dimmed with a clock while sending) and the working status shows with it, before validation or the network; the server's copy replaces it, never beside it. A send that is not confirmed keeps the message with « Non envoyé » and the Check / Retry notice; a refused one goes back to the composer. `packages/ui/src/native-chat.ts`, `chat-react-session.ts`, `registry/pi-chat/message.tsx`, `notice.tsx`.
- `chat-connecting` usable while the chat connects (D-1434): `useRemoteChat` hands out its controller with `status: 'connecting'` (with `actions` and `configure`, which wait for the connection) before the host's first view lands; `ready` still means the view landed, same controller. PiChat's composer takes messages before the first view: shown at once as the person's own, held by the controller (no second queue) and sent in order once connected; the transcript shows from the first view. A failed connect never sends them: the state turns `offline` and they come back in the next attempt's composer. `packages/ui/src/chat-react-remote.ts`, `chat-react-controller.ts`, `native-chat.ts` (`send`), `chat-react-session.ts`.
- `chat-send-timing` `getSnapshot().timing`: `inputReady` and, per send, `enter`, `shown`, `firstWords`, `done` (ms on `performance.now()`, also `performance.mark('boring-chat:<step>')`), for tests and harnesses. `packages/ui/src/native-chat.ts`.
- `chat-photo-links` a photo sent as a link (`{ type: 'image', data: '', url }`, the url relative to the chat endpoint) is drawn from that link in the message, the viewer and the artifact panel, in the live view and in earlier pages (the replica keeps the host's link; the resolved copy is derived after each replay); only http(s) links draw, and a missing or broken one shows a placeholder, never a broken image (D-1433). `packages/ui/src/remote-chat.ts`, `registry/pi-chat/composer.tsx` (`imageSource`), `message.tsx`, `image-viewer.tsx`.
- `chat-idle-poll` `useConversationsClient({ idlePollMs = 30000, pollMs = 4000, busy })`: the list refreshes every `idlePollMs` while visible and idle, every `pollMs` while `busy` (and `PiChat` reloads every 4 s while its turn runs, and once at its end; `registry/pi-chat/pi-chat.tsx`), never while the tab is hidden, and at once on visibilitychange, focus and turn end (D-1638). `packages/ui/src/chat-react-conversations.ts`. Drive: `node --test test/ui/conversations-idle-poll.test.mjs`.
- `chat-served-end` the host's `session_closed` end frame on an `op=watch` stream is drained to its close, not cancelled or aborted (no ERR_ABORTED), the watch reopens, and one stream is open at a time (D-1638). `packages/ui/src/remote-chat.ts`. Drive: `node --test test/packages/ui-remote-chat-served-end.test.mjs`.
- `chat-first-view-timeout` `createRemoteChat({ firstViewTimeoutMs })` (default 18000): a host that never sends the first view is an error with retry, not « Connexion… » for good. `packages/ui/src/remote-chat.ts`.
- `chat-projected-watch` with the transport's `project`, a watch sends the first projected view, then the operation batch between projected views (`diffRevisions`; the client replays it as it does native operations), so an update costs the same whatever the conversation holds: 62 KB per update became about 0.1 KB at 40 earlier turns, and the replica's unchanged entries keep their identity. A batch that is not under half the full view's size falls back to the full view. Raw operations never leave the host. `packages/agent/src/chat-transport.ts` (`frameEncoder`).
- `chat-plugins` `withChatPlugins(props)` fills every missing component and card. `registry/pi-chat-plugins/chat-plugins.ts`.

- `chat-history-retry` native older-page reads time out after 15 seconds, retain the prior page and permit retry; late results cannot replace accepted history. New native threads without a head boundary do not advertise nonexistent older records. Pages start below the view's first entry, so the first page never repeats what is on screen; a host view's `hasEarlier` (read with `viewHasEarlier`) shows or hides « earlier » and `false` ends it without a scan (D-1433). `packages/ui/src/native-chat.ts`, `registry/pi-chat/pi-chat.tsx`.

## How to get to it (user POV)

- Inside the agent layer, an agent workspace, the ambient bar or a bare `PiChat` page.
- Composer: type `/` for commands, `@` for files or entities, `+` to attach, tap the microphone to record.

## Gotchas

- A composer feature with no `Picker`/`Button` component renders nothing; install the item.
- Visual values are tokens only; `boring-ui-blocks check --design src` fails literals.
- `natural` presentation changes rendering only, never the stored history.
