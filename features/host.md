# Agent host

An app is one `defineApp` definition: its models, handlers, exposed operations, views, agents, wakes, seed and words. `@hachej/boring-agent/host` holds the contract a model may import, with the identity every model shares. Later cards mount it.

## Sub-features

- `host-contract` `defineApp` and `checkAgents` refuse a malformed definition at definition time and at mount, naming the app and the field: name, views, `expose`, needs, `units`, wakes, agent names, and the languages (a base the kit speaks, its words, `app.title` and one name per view). `packages/agent/src/host/define-app.ts`.
- `host-identity` `CurrentUser` (the person, and the scope an agent session carries), `Session`, `NotYours`, `NotAllowed`, `mustOwn` and `must`: the one rights rule over a unit's members, with roles ranked owner, editor, reader. `packages/agent/src/host/identity.ts`.
- `host-build` `npx boring-host-build <app dir> --options <module> [--shell <module>] [--page <html file>] [--stack <module>]` reads the app's `app.ts` and writes `.gen/server.ts` (the Worker entry, the only `Harness.open`), `.gen/assets.ts` (the page text and the skills as text), `.gen/page.tsx` (the shell and each view's module) and, with `--stack`, `.gen/alchemy.run.ts`. The same app gives the same text in any folder. A broken app folder is refused in one line and `.gen/` is left as it was. `packages/agent/src/host-build.ts`, `host-build-cli.ts`, `host-cloudflare/entry.ts` (the Worker entry's text, which imports nothing).
- `host-tools` `appTools` builds one agent's Domain operations (`expose[<agent>]`, through Domain's `toToolkit`) as one pi-durable Extension named `host.tools.<agent>`; each call builds the Domain Layer on the session's scope and the caller from `attribution(call, context)`, never from the model's arguments, and an unknown sender is refused without running anything. `checkExpose` refuses an exposed name that gives no tool, in any audience; `checkAgentTools` refuses an agent holding another agent's tools and a delegate holding an operation its caller does not. `packages/agent/src/host/runtime/tools.ts`.

- `host-session` `createSession` of `@hachej/boring-agent/host-runtime`: one neutral session per id, `me:<person>` (answers that person only, its tools carry no scope) or `reader:<unit>` (woken only by `wake(unit, event, key, text)` with the stable key of a declared wake policy (`policy.key`) as `event`, one reader agent per app (an app with wakes for two agents is refused), scope `{ kind: "reader", unit, role: "editor", ops: expose[<reader>] }` derived from its id). The Harness comes in through `openHarness` (law BORING-PI-2) and opens on first use, once; a failed open answers 503 `unavailable` and is not kept. `alarm()` resumes what a lost instance left and waits for it. The tools of each agent are one `host.tools.<agent>` Extension from the `tools` option (default `appTools`); the session keeps no list of tools. Files (`upload`, `read`, `write`, `edit`) exist only for a personal session of an app with `needs: ["files"]`. `packages/agent/src/host/runtime/session.ts`.
- `host-streams` The session's wire is the kit's chat transport (`createChatTransportHandler`): `?op=entries`, `?op=watch` (a heartbeat at once), `submit`, `answer`, `abort`. Every submit resolves the sender's language through `ResolveLanguage` and sends it as the first line of the message, `[language: fr]`; a model failure reaches every open watch as the run's `runFailure`, and the stream stays open.

## How to get to it (user POV)

- An app builder imports `defineApp` and the identity from `@hachej/boring-agent/host`. A person sees nothing yet: no page, no session.

## Driving it with node tests

Preconditions: `npm run build`; Domain, effect and alchemy installed (root dev dependencies); fictional data only.

- **Contract.** `host-contract`: `node --test test/packages/agent-host-contract.test.mjs` defines the two fixture apps (`fixtures/host-apps/`), prints one `caught:` line per planted fault and a `units:` line, and reads the built `dist/host.js` import graph. `npm run typecheck` compiles both apps and the closed shapes (`test/types/host-contract.ts`). `npm run test:host-consumer` installs the packed packages in a fresh folder.
- **Build.** `host-build`: `npm run build && node --test --test-name-pattern "build|broken folder" test/packages/agent-host-mount.test.mjs` runs the built command on copies of both fixture apps (two runs, two folders, byte-identical; the same `server.ts` for both apps; one line and an untouched `.gen/` for a broken folder). `npm run test:host-consumer` runs it from a packed install.
- **Tools.** `host-tools`: `npm run build && node --test test/packages/agent-host-tools.test.mjs` opens a Harness on a scripted model with Domain in memory, calls each agent's tools as a person, and plants the faults (another notebook in seven spellings, an unknown sender, an operation that does not exist, a reader holding the assistant's tools, a delegate holding a write its caller lacks).
- **Identity.** `host-identity`: the same test prints the twelve `must:` rows (no scope, a scope, a scope with `ops`).
- **Session.** `host-session` and `host-streams`: `npm run build && node --test test/packages/agent-host-session.test.mjs` runs `createSession` on pi-durable's SQLite storage in a temporary file, Domain in memory and a scripted model. It prints one line each for first use (one open, a heartbeat within 6 s), the turn that finishes after an eviction with only `alarm()` called, the failure both watches receive, each sender's language, the file tools, a reader's wake and the one extension per agent.

## Gotchas

- `boring-host-build` writes text only, and `--options` is required. One rule for every path flag (`--options`, `--stack`, `--shell`, `--page`): a path written `./x` or `../x` is relative to the app folder (the generated files say `../x`), an absolute path is rewritten relative to `.gen/` so no machine path reaches the text, a package name or an alias such as `@/components/app-host` is copied as given. A path flag that names no file is refused in one line. Bundling `.gen/page.tsx` is the caller's. `.gen/` is ignored by git and replaced whole through `.gen.tmp`: a failed build leaves the previous `.gen/`, and a stale `alchemy.run.ts` goes when `--stack` is not given. A `skills` path that leaves the app folder (links resolved) is refused.
- The options module must end with `satisfies HostOptions` (from `@hachej/boring-agent/host`). The generated `server.ts` spreads it, and a spread is not checked for unknown keys, so this is the only thing that catches a misspelt key such as `signup` for `signUp` (`test/types/host-options.ts`).
- **Running `boring-host-build` runs the app's `app.ts`.** It loads it with one `import()` (the one SELF-2 exception), with everything the caller has: the whole environment, and the right to write outside the app folder. Run it only on an app's own reviewed folder. **No guarantee against an `app.ts` that ends the process or fakes the writes:** it can exit 0 having written nothing (`process.exit(0)`, `process.reallyExit(0)`, an exit handler that sets `exitCode = 0`), or replace `node:fs/promises` and print a success line. Code that runs an app's own code cannot contain it from inside. A sandbox with no secrets and only the app folder writable protects the caller's secrets and files, but does not close this hole. A caller that must not ship a stale output deletes `.gen/`, builds, and after exit 0 checks that the files exist and that `server.ts` equals `entry(specifier(appDir, optionsFlag))`. `entry` (the frozen function of `host-cloudflare`) and `specifier` (the one function that turns a path flag into what `.gen/` says, such as `../options.ts`) are both exported by `@hachej/boring-agent/host-build`, so a Node-only caller loads no Cloudflare. That check belongs to the platform's ship path: boring-studio's `ship-deploy` and `deploy-user` cards own it and the sandbox. A view `component` or a skills folder that leaves the app folder (links resolved) is refused, and the build works in unique `.gen.tmp-*` and `.gen.old-*` folders, so a leftover never blocks the next one; a build removes leftovers of those two names older than ten minutes and touches nothing else.

- `./host` imports only Domain, effect and type-only pi; `cloudflare:*`, `node:*` and `alchemy` are forbidden in `src/host/` and `src/host.ts` (`ARCHITECTURE.json` `pathRules`).
- `defineApp` cannot see agent names; `checkAgents(def, agents)` runs at mount.
- Every declared language is checked against the base's keys (the title, each view's name, each refusal): a table that is not an object, lacks one, or has a view or refusal the base has not, is refused at `defineApp` (AP-23).
- Domain, effect and alchemy are not declared as peers of `@hachej/boring-agent`: npm walks the optional peers of Domain (react, ws) and refuses a plain install next to pi 1.5.2 (ERESOLVE). An app that imports `./host` installs the three itself, at the versions of this repository's root dev dependencies; an app that does not installs none of them. `npm run test:host-consumer` does both real installs.
- A host consumer who has not installed the three packages gets one sentence from `@hachej/boring-agent/host` naming each with its exact version (`HOST_PACKAGES`, tested against the root dev dependencies). The entry loads its contract with a dynamic `import()` for this; a consumer that never imports it installs nothing.
- Languages and Chord: `@earendil-works/chord` 1.5.2 has `defineMessages`, `Translations`, `formatNumber` and `formatTime` at its root, but they do not serve this contract. Checked in `node_modules` and by running it: `defineMessages` checks a catalog's keys only in the types (missing, extra, a string and a nested table are all accepted at run time), its catalogs are flat strings or functions in one namespace (ours are nested: `app`, `views.<id>`, `refusals.<tag>`), it renders in an ambient current language (a surface's), not a person's language passed per request, and `formatNumber`/`formatTime` cover two of `Format`'s eight methods in that same ambient language. `resolveLocale`, `matchLocale` and `canonicalLocale` are not exported from the package. Kept of ours: the `languages` declaration, the `Format` type (implemented on `Intl` by the runtime card) and the run-time key check in `defineApp`, which names the app and the field. Revisit when Chord exports its locale functions or a catalog check at run time.
