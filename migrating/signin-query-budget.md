- **`@hachej/boring-ui-kit/signin`: sign-in costs a few D1 statements per request, not about 97 (fix, no API change; drop any patch of 0.5.x).** `makeAuth` now keeps the Better Auth object per isolate and database binding (keyed by the binding, secret, origin, app name, first-owner hash, Google client, Studio link, provider flag and sign-up limit), runs the migration once per binding (a failed run is retried at the next request) and sets `advanced.database.validateSchema: false`. The first-owner proof is read from the sign-up's own `x-boring-first-owner` header, not kept between requests. An app that patched kit 0.5.23 with the same two changes (migrate once, `validateSchema: false`) drops its patch on this release; keep calling `signIn(...)` per request, it now reuses the built object. New: `@hachej/boring-ui-kit/signin/testing` (`countingD1`, `measureSignInQueries`, `assertSignInQueryBudget`, `resetSignInCaches`): add one test per app, `await assertSignInQueryBudget({ build: (database, firstOwnerHash) => signIn({ database, firstOwnerHash, ...yourOptions }) })`, which signs a fictional first owner up, drives 100 signed-in requests on a counting fake D1 and fails above 10 statements per request.
- **`@hachej/boring-ui-kit/visible-interval` (additive): `useVisibleInterval(callback, ms, { idleMs: 600000 })` for screen timers.** It runs only while the tab is visible, pauses when hidden, calls once on return, stops after ten minutes without pointer, key or touch activity (and restarts on the next) and clears on unmount. Use it for every `setInterval` that polls the server from a screen. The `pi-app` blocks `use-new-version`, `use-saved`, `artifact-panel` (revision history) and `file-viewer` (text files) now use it and import it from the kit: re-run `boring-ui-blocks update pi-app`; a text file or history that is left untouched for ten minutes stops refreshing until the person moves.
