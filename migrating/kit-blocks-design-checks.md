- **Kit blocks pass their own design checks (same look, no action needed).** The kit's own scan (`scripts/check-design.mjs`) now applies `design-z-index`, `design-type-scale` and `design-gap-not-space` to the block TSX too. The blocks stack on named layers instead of `z-10`: `app.css` adds `--z-behind` (-10), `--z-above` (1), `--z-drop` (5), `--z-raised` (10), `--z-lifted` (20) and `--z-fullscreen` (45), `--z-tools` (300) with `z-behind`, `z-raised`, `z-lifted`, `z-fullscreen` and `z-tools` utilities; every number is unchanged. The registry `theme` item carries the same `z-*` utilities, with the number as fallback, so a page that compiles only the theme (a test harness) has them. The app-shell's custom properties `--app-shell-z-tabs|peek|layer|sheet|point` are now `--z-app-shell-tabs|peek|layer|sheet|point` (an app that read one in its own css renames it). An app that passed `className="z-50"` to a block whose default layer is now `z-sheet` keeps both classes (tailwind-merge does not know the names): pass a layer name too.
