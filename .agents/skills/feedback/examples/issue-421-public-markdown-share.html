CLI Review Draft: Lightweight Share Links

This review draft proposes a small public surface for sharing a Markdown document and its embedded local images with an external reviewer.

Intended behavior: the share token grants access to this entry Markdown file plus dependency URLs that were resolved from the document at share time.

Why this exists

CLI users often need a quick review link for a design note, plan, or generated report. A narrow public page avoids asking reviewers to open the full Boring workspace just to read one Markdown document.

Local image dependency

The Markdown can reference local images such as ./images/flow.png. The share service serves only those dependencies through scoped asset URLs.

Optional public edit mode

Edit mode must be explicit at share creation time, visually obvious to the reviewer, and limited to the entry Markdown file. Image uploads, folder edits, arbitrary file writes, shell commands, and agent actions remain unavailable.

Edit mode is a separate capability and edits only docs/review/design-note.md

Safety boundaries

✓Render the selected Markdown document and sanitized local image dependencies.
✓Allow edits only when the public link includes an explicit edit capability for the entry file.
×No full workspace chrome, file explorer, project list, or hidden adjacent files.
×No terminal, agent APIs, plugin admin routes, environment variables, or arbitrary path fetches.

Resolved assets

Only image paths referenced by the Markdown are available to the page.

  • ./images/share-flow.png → allowed
  • ./images/screenshot.png → allowed
  • ../secrets.env → blocked
  • /workspace/** browsing → blocked

CLI mental model

boring share markdown docs/review/design-note.md --public

Optional edit mode should require a conspicuous flag, for example --allow-edit-entry, and the public UI must label that state clearly.

Artifact scope: static UX prototype only. It contains no production app code, no network calls, and no dependency on the Boring workspace runtime.
