# @hachej/boring-browser

The opt-in agent worker of BORING-PI-5: everything a host needs to run the unchanged native Pi kernel, model calls and
pi-codemode inside a browser tab, in a dedicated Web Worker that the page reaches only through a request transport. The UI
bundle stays free of it. Every entry is optional and browser-safe unless it says Node; `examples/browser-agent` is the
working composition and its journey runs it in headless Chromium.

Agent features that also work here live in their own packages: the approval gate and OptChat memory in
[`@hachej/boring-agent`](../agent/README.md), the SQLite-backed git workspace in
[`@hachej/boring-execution/virtual-sqlite`](../execution/README.md#virtual-repository-saved-in-sqlite).

## Worker, storage and models

- `@hachej/boring-browser/transport`: `serveRequests(route)` in a Web Worker answers Requests and `connectWorker(url).fetch` in the page sends them over postMessage, with transferred streaming bodies and abort. The chat stack cannot tell it from a server.
- `@hachej/boring-browser/sqlite`: `openBrowserSqlite(file, { wasmUrl })` returns pi-durable's `SqliteDatabase` over SQLite Wasm and the `opfs-sahpool` VFS (memory fallback when OPFS is missing); `openBrowserSqliteConnection(file, { wasmUrl })` opens another file of the same pool as a synchronous `SqliteConnection` (`@hachej/boring-files/sqlite`) for the SQLite workspace backend (`@hachej/boring-files/sqlite-filesystem`); `wipeBrowserSqlite`. The VFS lets one tab hold the database: a second tab's `openBrowserSqlite` rejects with `BrowserSqliteLockedError` (`code: 'sqlite-locked'`, a sentence for the person as its message) instead of quietly using a memory database that would lose data; `isBrowserSqliteLocked(error)` also recognizes it after a worker boundary, where `connectWorker(...).ready` rejects with the same `code` and message. `@hachej/boring-browser/build` (Node) returns the wasm files to serve, which must be cross-origin isolated.
- `@hachej/boring-browser/models`: `openBrowserModels({ db, providers, defaultModels? })` registers any pi-ai providers (or factories) over a SQLite `CredentialStore` and offers `catalog()` for a settings UI (`configured` is pi-ai's own auth resolution), `saveApiKey` and `loginDeviceCode` (OAuth device code). It registers pi-ai's statically linked OAuth flows (`registerBunOAuthFlows` from `@earendil-works/pi-ai/bun-oauth`) itself, because pi-ai otherwise loads them through an import a bundler cannot follow and a bundled worker fails with "Failed to fetch dynamically imported module"; consumers do nothing. The bundle then contains every pi-ai OAuth flow (about 0.2 MB); the Node modules some flows import resolve to the `@hachej/boring-browser/build` shims. Which model a conversation uses is not stored here: it stays in the conversation's native agent configuration.
- `createModelAccessHandler(browserModels, conversation, context, { prefix? })` (same entry) is the worker half of the `provider-setup` registry item for one native conversation: one `Request => Response | undefined` function, no router. `GET <prefix>` returns `{ settings, providers, login }` (default prefix `/api/model`), where `settings` is the conversation's own model (`conversation.agent()`); `PUT <prefix>` takes `{ provider?, modelId?, apiKey? }`, saves the key and calls `conversation.configure({ model })`; `POST <prefix>/login` takes `{ provider }` and answers once the device code is known (or the start failed); `login` is the item's `loginState`. A finished sign-in selects that provider. Anything else returns `undefined`, so mount it first in the worker's route and fall through. `handler.state()` returns the same object for a host route that adds more state. Routing model calls through a proxy (for a provider that refuses browser calls) is host policy: `examples/browser-agent` shows one.

## Code mode and bundling

Run Pi, upstream pi-codemode, just-bash and isomorphic-git in a browser bundle without forking anything. `@hachej/boring-browser/build` (Node, build time) provides `browserBundleOptions(side, { minify? })` for esbuild (`side` is `page`, `agent` or `codemode`; `minify` defaults to false so a bundle stays readable while you debug it), which maps Node built-ins to small shims (`path`, `crypto`, `worker_threads` for the host and the worker, stubs for `zlib`/`fs/promises`/`module`/`http`) and injects `Buffer` for the agent bundle (install `buffer`). `codemodeWorkerEntry()` is the file to bundle as the nested code-mode worker (`@hachej/boring-browser/codemode-worker`, which imports `@earendil-works/pi-codemode/worker` unchanged), and `quickjsWasm()` returns the QuickJS wasm to serve. In the page or worker, `browserCodemode({ wasmUrl, workerUrl })` returns `{ wasm, workerUrl }` for `new CodemodeSandbox({ ...options, tools })`. The page must be cross-origin isolated. Only tools you pass to the sandbox are callable from code; keep approval-gated tools out of it (see the [approval gate](../agent/README.md#approval-gate)).
